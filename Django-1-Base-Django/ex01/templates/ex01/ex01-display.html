Displaying a simple static page in Django follows a well-defined path, from the moment the browser sends a request to the moment it receives the finished HTML response.

  1. The request arrives. The browser sends an HTTP request (for example a GET request to /ex00) to the Django development server started with manage.py runserver.
  2. The URL dispatcher takes over. Django's URL resolver reads the project's root urls.py and looks for a pattern that matches the requested path. When it finds a match, it calls the associated view function, usually forwarding it to the application's own urls.py via include().
  3. The view is executed. The view function (in views.py) receives the HttpRequest object, runs whatever logic is needed (here, none, since the page is static), builds a context dictionary of variables to pass to the template, and calls render().
  4. The template engine renders the HTML. render() loads the requested template file, replaces every template tag and variable with real data from the context, and produces a complete HTML string.
  5. The response is sent back. The rendered HTML is wrapped in an HttpResponse object and sent back to the browser, which then displays the page to the user.

Summary

Request → URL dispatcher → View → Template engine → Response → Browser display.
